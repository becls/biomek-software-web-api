# Script

| Property | Value |
|----------|-------|
| stepType | `"Script"` |
| Category | Leaf |
| Terminator | N/A |
| Compatible Hardware | All |

> Base keys + casing: see [Base Keys & Serialization Conventions](00-Base-Keys-and-Conventions.md).

> **Scripting is an advanced capability — use it as little as possible.**
> Prefer a dedicated step over a script wherever one exists: to persist a value, use the
> **[Set Global](69-Set-Global.md)** step, not a script. For anything beyond a trivial calculation
> (or the HTML editor panel described under Advanced), contact Beckman Coulter for applications support.
> The examples here are intentionally minimal.

## Behavior Summary

The Script step executes a VBScript or JScript `code` block. Code is executed
both at enqueue (validation) time and at runtime. The step is a **leaf**: no child steps, no scoped variables.

Scope:

- To define variables for child steps, use [Let](56-Let.md) or [Scripted Let](67-Scripted-Let.md). `Extend` / `WeakExtend` are not supported in a Script step (see Common Mistakes).
- To persist a value, use the [Set Global](69-Set-Global.md) step rather than scripting it.
- Method variables are read by their **bare name**.

Keep any script trivial: a small, self-contained calculation.

## Parameters Reference Table

| Key | Type | Units | Required | Default | Description |
|-----|------|-------|----------|---------|-------------|
| `code` | `string` | — | **Yes** | `""` | Script code to execute. Always author this key, even if it is empty. |
| `description` | `string` | — | **Yes** | `""` | Human-readable description displayed in the step caption. Omission raises a missing-key SYSTEM ERROR. |
| `language` | `string` | — | No | `"VBScript"` | Script language ProgID. Author it explicitly — `"VBScript"` or `"JScript"` — rather than relying on either default. |
| `let` | object | — | No | *(none)* | Free-form dictionary that some Script steps carry. The step's enqueue does **not** read it: it is neither a child scope (Script is a leaf) nor a step-parameter override. Where it is populated it is authored data that the step's **own script** reads (`StepDictionary.Let`). Preserve verbatim when round-tripping; do not author it for a new script. |

Universal base keys (`caption`, `stepUI`, `disabled`, …) — see [Base Keys & Serialization Conventions](00-Base-Keys-and-Conventions.md).

If any additional keys appear on a `Script` step in an exported method, they do not impact the behavior of the Script step. Preserve them verbatim for round-tripping.

## Cross-Field Validation Rules

1. `code` must be valid syntax in the selected `language`; parse/runtime errors
   surface at execution. Newlines may be authored as `\r\n` or `\n`, but `\r\n`
   is preferred as that is the format generated by the UI.
2. Read a method variable by its **bare name** (not `VARIABLES(...)`). Using workspace variables is an advanced capability and is not covered here. Do not manipulate Biomek globals from a script — use the [Set Global](69-Set-Global.md) step.

## Structural Context

This step is a leaf and does not support subSteps.

## Canonical Examples

Minimal VBScript that executes cleanly (no external object refs — the safest baseline):

```json
{
  "stepType": "Script",
  "parameters": {
    "code": "Dim n\r\nn = 1",
    "description": "Minimal no-op VBScript",
    "language": "VBScript"
  }
}
```

Minimal JScript equivalent:

```json
{
  "stepType": "Script",
  "parameters": {
    "code": "var n = 1;",
    "description": "Minimal no-op JScript",
    "language": "JScript"
  }
}
```

`code` is a single JSON string; embed line breaks as `\r\n` (CRLF) to match Biomek's
Windows-native line endings.

## Common Mistakes

- **Using `MsgBox`**: not available in the Biomek script host — it errors. Use a Pause step for an operator message.
- **Calling `Extend` / `WeakExtend`**: unsupported in a Script step — the calls fail as an unsupported-command error. Use [Scripted Let](67-Scripted-Let.md) to bind variables for child steps.
- **Setting a global from a script**: don't — use the [Set Global](69-Set-Global.md) step. Manipulating globals or the workspace from a script is an advanced capability, not covered here.
- **Reading a variable with `VARIABLES("x")`**: fails as an object-expected error — read the variable by its bare name instead.
- **Expecting the code to run when the step is reached**: Biomek steps run as
  soon as their required resources are available. If the script does not utilize
  any Biomek workspace resources, it will run ahead of the surrounding physical
  steps, in addition to running at enqueue (validate) time. Don't use a
  script to react to something that happens during the run.
- **Confusing with Scripted Let**: Script is a leaf — it doesn't define scoped variables for child steps. Use Scripted Let to bind variables for a group of children.
