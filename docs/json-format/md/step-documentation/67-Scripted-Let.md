# Scripted Let

| Property | Value |
|----------|-------|
| stepType | `"Scripted Let"` |
| Category | Container (free-form) |
| Terminator | `"End"` (caption: "End Scripted Let") |
| Compatible Hardware | All |

> Base keys + casing: see [Base Keys & Serialization Conventions](00-Base-Keys-and-Conventions.md).

> **Scripting is an advanced capability.** Prefer a dedicated step wherever one exists. A
> Scripted Let runs a script whose only supported purpose is defining variables for its child
> steps. For anything beyond that, contact Beckman Coulter for applications support.

## Behavior Summary

The Scripted Let step runs a VBScript or JScript block, then enqueues its child steps in a scope containing the variables the script bound. Children read those variables with `=VariableName`.

The script binds a variable by calling the global command **`Extend "name", value`** (VBScript) or **`Extend("name", value)`** (JScript); `WeakExtend` binds the same way but defers to an existing outer definition of that name. Both are **bare** global commands, not members of a named object.

Inside the script, any variable that is in scope at this step is readable by its **bare name** (not via `VARIABLES(...)`).

The bindings are visible only to the step's descendants; they go out of scope
when execution leaves the container, so a step placed after the `"End"`
terminator cannot reference them.

Do not author any other script commands besides `Extend` or `WeakExtend` in a
Scripted Let step. If other commands exist, preserve them for round-tripping.

## Parameters Reference Table

| Key | Type | Units | Required | Default | Description |
|-----|------|-------|----------|---------|-------------|
| `code` | `string` | — | **Yes** | `""` | Script code to execute. The script runs before child steps are enqueued. Always author this key. |
| `description` | `string` | — | **Yes** | `""` | Human-readable description; the editor uses it as the step caption when no `caption` override is set. |
| `language` | `string` | — | No | `"VBScript"` | Script language ProgID — see Language Values below. If omitted, the step also falls back to `"VBScript"` at enqueue. Author it explicitly. |
| `let` | `object` | — | No | *(none)* | **Inactive — overwritten at runtime. Never author.** |
| `weak` | `object` | — | No | *(none)* | **Inactive — overwritten at runtime. Never author.** |
| `prompt` | `object` | — | **Yes** | `{}` | Names to prompt the operator for at run time. Only the **key** is used — the stored value is never read, so author it as `null`. The dialog message and title are generated automatically (`Enter a value to use for '<name>'`, title `Enter Value`) and the default offered is the value the script bound for that name. A prompted name therefore has an effect only if the script also binds it with `Extend`/`WeakExtend`; a `prompt` entry with no matching binding produces no dialog. Unlike `let`/`weak`, this key is **not** reset at enqueue, so omitting it fails at Run as a missing-key SYSTEM ERROR. |

Universal base keys (`caption`, `stepUI`, `disabled`, …) — see [Base Keys & Serialization Conventions](00-Base-Keys-and-Conventions.md).

If any additional keys appear on a `Scripted Let` step in an exported method,
they do not impact the behavior of the Scripted Let step. Preserve them verbatim
for round-tripping.

## Cross-Field Validation Rules

1. `code` must be valid syntax in the selected `language`; parse/runtime errors
   surface at execution. Newlines may be authored as `\r\n` or `\n`, but `\r\n`
   is preferred as that is the format generated by the UI.
2. Add variables with the **bare** global commands `Extend`/`WeakExtend` (never `EXTENDED_COMMANDS.Extend`). Read in-scope method variables by their bare names.
3. A name listed in `prompt` produces an operator dialog only if the script also binds that same name with `Extend`/`WeakExtend`.

## Structural Context

The Scripted Let step is a **free-form container**. It requires one child:

- **Trailing anchor**: `"End"` with caption `"End Scripted Let"`.

**Constraints**:

- `subSteps` must be present and contain at least the `"End"` terminator as the last element.
- Any number of operational steps may be placed before the `"End"` terminator.
- Child steps can reference variables defined by the script via `=VariableName` syntax.

## Canonical Examples

Define one variable in VBScript — the default form (the editor's language selection defaults to VBScript, so that is what a step carries unless the author picks JScript):

```json
{
  "stepType": "Scripted Let",
  "parameters": {
    "code": "Extend \"mixVolume\", 42",
    "description": "Define mixVolume",
    "language": "VBScript",
    "prompt": {}
  },
  "subSteps": [
    { "stepType": "Comment", "parameters": { "description": "child steps use =mixVolume" } },
    { "stepType": "End", "parameters": { "caption": "End Scripted Let" } }
  ]
}
```

A child step consumes the binding by writing `"=mixVolume"` in any expression-capable field — for example a Transfer step's volume. After the `"End"` terminator the name is out of scope again.

The same in JScript (parentheses + semicolon).

```json
{
  "stepType": "Scripted Let",
  "parameters": {
    "code": "Extend('mixVolume', 42);",
    "description": "Define mixVolume",
    "language": "JScript",
    "prompt": {}
  },
  "subSteps": [
    { "stepType": "Comment", "parameters": { "description": "child steps use =mixVolume" } },
    { "stepType": "End", "parameters": { "caption": "End Scripted Let" } }
  ]
}
```

## Common Mistakes

- **Forgetting the `"End"` terminator**: Scripted Let is a free-form container and must end with `"End"`.
- **Omitting `prompt`**: unlike `let`/`weak`, `prompt` is not reset, so a missing key raises a missing-key SYSTEM ERROR. Include `{}`.
- **Authoring `let` or `weak`**: the step overwrites both with empty dictionaries before the script runs and removes them afterwards, so any authored value is discarded. Bind variables from the script instead.
- **Expecting a `prompt` value to be the message**: only the key matters. The message is generated from the variable name, and the name must also be bound by the script or no dialog appears.
- **Prefixing the command with `EXTENDED_COMMANDS`**: call `Extend`/`WeakExtend` as **bare** global commands. `EXTENDED_COMMANDS.Extend …` fails at run as an object-required error — the name is not a referenceable object.
- **Referencing a script variable after `"End"`**: the binding is out of scope; the method fails validation as a not-defined-variable error.
- **Wrong language syntax**: JScript — `Extend('name', value);`. VBScript — `Extend "name", value`; do not wrap the whole argument list in parentheses (`Extend("name", value)` is a VBScript syntax error). `Extend("name"), value` parenthesizes only the first argument and is also valid VBScript — leave it alone when round-tripping.
- **Confusing with Script step**: Script is a leaf step that just executes code. Scripted Let is a container that also defines scoped variables for its children.
